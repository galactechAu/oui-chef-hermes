# Security policy

## Reporting a vulnerability

Please do not disclose unpatched vulnerabilities in public issues. Until GitHub private vulnerability reporting is enabled for the future repository, contact the repository owner privately through the repository profile/contact channel.

Include a clear reproduction, affected version/commit, impact, and any suggested mitigation. Do not include credentials or personal data.

## Scope

Particularly sensitive areas include public-URL validation, import/transcription boundaries, the optional Hermes bridge, JSON persistence, and accidental exposure of runtime secrets or data.

The Hermes bridge must remain private and operator-controlled. Reports involving third-party platforms must not attempt to bypass authentication or access restrictions.
